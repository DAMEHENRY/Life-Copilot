# Life 本地语义检索

在这台 Mac 上给日记和 AI 对话记录建向量索引，按意思而不是关键词找过去的事。模型是 `microsoft/harrier-oss-v1-0.6b`，检索和索引计算全程本地运行，也不会联网检查模型更新。

## 怎么用

- 首次使用或缓存缺文件时，在可联网的环境运行 `python3 tools/recall/recall.py download-model`，从 Hugging Face 下载模型（约 1.1GB）；已有完整缓存则不需要。
- 搜索：`python3 tools/recall/recall.py search "在图书馆复习到很晚的那天" "stayed late studying in the library" 2>/dev/null`（抑制模型加载进度；退出失败时另查错误，不把失败当成零命中）。
- 每次搜索前会自动把新增或改过的文件补进索引，平时几秒钟；没有后台定时任务。
- 分析某一天时只看那天及以前的内容，避免用后来的内容解释当时：加 `--before YYYY-MM-DD`。
- 只看手写原文：加 `--kinds handwritten`。
- 手动全量重建：`python3 tools/recall/recall.py index --full`；看索引状态：`python3 tools/recall/recall.py status`。

## 加载与等待

- 普通搜索只加载本机缓存；缓存缺失会直接提示下载命令，不会在后台反复尝试联网。
- 加载时会显示使用 CPU 还是 MPS，以及模型就绪所用时间；受限运行环境可能只能使用 CPU。
- 另一个检索正在更新索引时，会显示等待提示，最多等 30 秒后退出；稍后重试即可。若明确接受尚未更新的内容，可以用 `search --no-update` 搜索已经保存的索引。

## 怎么搜更准

- 用当时发生的具体细节去搜（在哪、和谁、做了什么），不要只用现在给这件事起的名字。
- 中文、英文各搜一次，日记两种语言都有。一次调用可以传多个查询。
- 结果只是候选，命中后按下面的方法选择原件并展开，引用前读原文。

## 命中后读取原件

这套工具输出文件路径、来源标签和行号；默认显示的短摘录只负责定位，JSON 里的切块也不是完整事件。目前没有自动识别事件边界、自动展开连续对话的子命令；文件读取已足以完成追读，不需要重新建索引。

- 问怎样回望一天，读原始日记并分清手写、合并补记与 Copilot 回应；长期记忆、人物页用于背景和定位。
- 问当时怎样交流，读 From Kai 指向的相应原始 trace。Kai 对应 `*-openclaw-trace.md`；连续读双方的话，保留 Henry 怎样讲、AI 怎样回应、Henry 怎样回应它。原始 trace 是当场对话的证据；其中引用的旧事、后来的复述与 AI 解释仍需分清，不能把所有对话记录一律当成复述，也不能把 AI 的解释当作 Henry 的事实。
- 从命中位置向前、向后读取完整消息或段落，覆盖相关事件的起因、过程、补充纠正和后续变化。先用 `command grep -n` 列出时间与消息位置，再用 `sed -n '起行,止行p' <path>` 分段读；一次一份文件的一段，不把多份长文拼进同一输出。在内部记住已读到的完整消息与下一行，连续接读；截断位置不明则拆小重读未确认范围，不能只挑几句核对便跳到回复。时间空白和固定行数不代表事件结束，同一件事稍后继续时还要定位追读；读到事件或话题边界即可，无需默认读取整天或全部历史。
- 是否读够，看这些背景是否改变了当前理解与回应，而非是否核对了一句旧话或加了日期。只表达真正相关的部分，不展示长篇历史，不据此自动推断他人心理或给建议。

Kai 使用的是 OpenClaw 的 `memory_search` 定位、`memory_get(path/from/lines)` 或文件读取工具续读；未归档会话需用可用的会话历史工具取连续正文。这里的 Mac 脚本不是 Kai 语义搜索的前置依赖。Kai 的完整运行流程以 `prompts/telegram-entry.md`「本地检索」为准；本说明提供 Mac 读取方法，不要求普通 Chat 启动 Diary Mode。

## 索引了什么

- `journal/YYYY/MM/` 下的日记，和 `journal/ai-conversations/` 下的对话记录；不含记忆文件、resources、archives。
- 每一块标了来源：手写、转写（带「对话转写」标注的段落）、分析（Copilot 写的段落）、对话记录。
- `data/` 里是切块原文和向量，属于私密内容，已写进 `.gitignore`；工具代码和这篇说明会进 git。
